# Prompt

记录提示词设计、业务上下文沉淀、结构化输出与效果评估实践。

Prompt 不是一句“让模型写得更好”的咒语。更可靠的做法是先把问题、约束、资料来源与验收标准说清楚，再让模型进入生成、分析或执行环节。

## 核心文章

- [提示词不是咒语：先让 AI 理解你的业务上下文](/ai/prompt/context-first-prompting/)

## 这个栏目关注什么

- **问题澄清**：先区分表面任务和真正要解决的业务问题。
- **上下文资料库**：沉淀产品、用户、品牌、案例和输出规范，避免每次从零介绍。
- **示例与约束**：使用优秀案例提供方向，同时让模型区分事实资料与可参考表达。
- **输出验收**：明确格式、长度、禁区、核验项与下一步动作。

## 一个实用原则

当产品参数、活动规则或业务事实不完整时，先要求 AI 列出缺失信息和待确认假设，不要急着生成最终内容。这样可以减少看似流畅、实际上与产品不符的输出。
