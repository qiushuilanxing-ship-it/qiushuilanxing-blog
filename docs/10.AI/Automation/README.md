# AI自动化

AI 自动化不是把几个节点连起来，而是把触发、上下文、决策、执行和反馈组织成一条**可观察、可恢复、可人工介入**的业务链路。

这里记录利用 AI、工作流引擎与自动化工具提升业务效率的实践，重点关注“自动化做什么、依据什么做、失败后怎么处理”，而不只展示工具界面。

## 自动化的五层结构

```text
触发器 → 上下文整理 → AI / 规则决策 → 外部执行 → 反馈与审计
```

| 层次 | 要解决的问题 | 典型能力 |
| --- | --- | --- |
| 触发器 | 什么时候启动流程 | 表单提交、消息事件、定时任务、异常事件 |
| 上下文整理 | 给后续节点提供什么事实 | 数据清洗、字段映射、文件解析、对象关联 |
| 决策 | 是否可以继续、该走哪条分支 | LLM 判断、规则判断、知识检索、人工审批 |
| 外部执行 | 如何把结果送到业务系统 | API 调用、数据库写入、消息通知、任务创建 |
| 反馈与审计 | 如何知道流程是否真正完成 | 状态回写、重试、幂等、告警、人工复核 |

## Coze 工作流

Coze 适合快速把模型、知识库、工具调用和业务分支组合成 AI 应用。实际设计中，更值得关注的是节点的输入输出契约、异常分支、工具权限和人工审核点，而不是节点数量。

- 关注：节点设计、知识库连接、工具调用、Agent 流程编排
- [查看 Coze 工作流使用教程](https://lcnu9zjo6wvs.feishu.cn/wiki/N9AFw7JXciTtEqkN2U8cvt5WnLh?from=from_copylink)

## n8n 自动化

n8n 一类低代码平台更适合连接 API、数据库、表格、消息系统与定时任务。它可以承担“系统间搬运和编排”的角色，并在需要语言理解或内容生成时调用 AI 能力。

- 关注：API 连接、数据流转、定时任务、失败重试、人工审批
- [参考自动化平台](https://studio.lingzhiai.com.cn/)

## AI内容生产流水线

内容生产不应止于“生成一段文本”。更完整的流程应包含素材接入、结构化提取、提示词生成、人工审核、发布交付与版本留痕。

## AI巡检系统

巡检自动化的价值在于把异常发现、去重告警、责任通知、恢复确认和报表沉淀连接起来。模型与规则负责发现问题，是否升级、如何处置仍需要明确的业务流程。

- 实践关联：[LiveInspector - AI直播智能巡检平台](/projects/live-inspector/)
